# 설계안 — 오늘의 퀘스트 · 진행 트래커 (Curriculum Progress Tracker)

> **한 줄:** `사업_데일리루틴_커리큘럼.md`(12주 5막)를 플랫폼 안으로 가져와, 홈을 열면
> **"오늘 뭘 하면 되는지 + 내 스트릭 + 다음 마일스톤"** 이 바로 보이게 한다. 1인 창업의
> 최대 적인 **흐지부지**를 코드로 막는 층.
>
> 상태: **✅ 구현 완료** (2026-09-04). 위치: 시작(홈) · 전용 페이지 `오늘·진행`. **원칙: 가벼움 — 하루 1~2분.**
>
> **구현 메모:** 편집 함수는 별도 `progress_edit.py` 대신 `curriculum.py`에 합침(로직과 같은 자리).
> 홈은 2열 레이아웃으로 개편(오늘 퀘스트·오늘 할 일 / 현황·마일스톤), 사용법은 접이식으로 이동.

## 1. 왜 필요한가

플랫폼은 STEP 도구(페이지)는 촘촘한데, **"루틴·진행"을 붙들어주는 층이 없다.** 커리큘럼은
님의 **흐지부지 방지 엔진**인데 지금은 플랫폼 밖 **죽은 MD 파일**로만 있다. 매 데스크 데이마다
어차피 켜는 플랫폼에 이걸 얹으면, **"오늘 뭘 해야 할지 몰라 멈추는 것"**(님이 꼽은 창업 최대 적)을
직접 없앤다.

**설계 대전제(볼륨 제약):** 하루 20~40분 데스크 데이 + 주말 랩. 그래서 이 기능은 **무거운 분석이
아니라, 하루 1~2분 체크로 리듬을 유지**시키는 게 전부다. 판매·채널·CRM 같은 **출시 후·고volume
도구는 파킹**한다.

## 2. 핵심 설계 결정

1. **완료 기반 진행(날짜 강제 아님).** "Week 3이니 Week 3을 해라"가 아니라 **"다음 미완료 퀘스트"**
   를 짚어준다. 결석해도 진도가 안 밀린다 → 커리큘럼 철학("다시 오면 됩니다", "결석 OK")과 일치.
   `D+n`은 **표시용**(시작일 기준)일 뿐 진도를 강제하지 않는다.
2. **데이터 2개.** 프로그램 정의(`curriculum.yaml`, 리포지토리 포함)와 내 상태(`progress.yaml`)를 분리.
3. **홈 위젯(요약) + 전용 페이지(전체).** 홈엔 오늘 퀘스트만, 페이지엔 전체 지도·마일스톤·보고 로그.
4. **데스크/랩 자동 필터.** 평일이면 데스크 퀘스트, 주말이면 랩 퀘스트를 먼저 보여준다(토글 가능).
5. **흐지부지 방지 장치를 코드로.** 스트릭·연속 2회 결석 경고·10분 법칙·다음 퀘스트 자동 안내.

## 3. 데이터 모델 (`core/models.py`, `extra="forbid"`)

```python
# --- 프로그램 정의 (data/curriculum.yaml, reference) ---
class Milestone(BaseModel):
    model_config = ConfigDict(extra="forbid")
    badge: str          # "안전한 실험자"
    dod: str            # 완료 조건(DoD) 설명

class Act(BaseModel):
    model_config = ConfigDict(extra="forbid")
    id: str             # "act1" … "act5"
    title: str          # "랩 온보딩"
    weeks: str          # "Week 1" (표시용)
    goal: str
    milestone: Milestone

class Quest(BaseModel):
    model_config = ConfigDict(extra="forbid")
    id: str             # 고유 "act1-desk-1"
    act: str            # act id
    week: int | None = None
    kind: str           # "desk" | "lab"
    text: str
    est_min: int | None = None

class Curriculum(BaseModel):
    model_config = ConfigDict(extra="forbid")
    acts: list[Act] = Field(min_length=1)
    quests: list[Quest] = Field(min_length=1)

# --- 내 상태 (data/brand/progress.yaml) ---
class DailyReport(BaseModel):
    model_config = ConfigDict(extra="forbid")
    date: date
    did: str = ""               # 오늘 한 것
    blocked: str | None = None  # 막힌 것/질문
    next: str | None = None     # 내일 할 것
    ten_min: bool = False       # 10분 법칙으로 출석한 날

class Progress(BaseModel):
    model_config = ConfigDict(extra="forbid")
    start_date: date | None = None   # D0 (장비·원료 세팅 끝난 날)
    done: list[str] = Field(default_factory=list)   # 완료한 quest id
    reports: list[DailyReport] = Field(default_factory=list)
```

**`data/curriculum.yaml` 예시(ACT 1만 — 구현 시 MD의 5막 12주 전체를 이 형식으로 옮김):**

```yaml
acts:
  - id: act1
    title: 랩 온보딩
    weeks: Week 1
    goal: 제품은 안 만든다. 안전·도구·측정·습관을 익힌다.
    milestone: {badge: 안전한 실험자, dod: 안전 세팅 + 측정값 3개 + 보고 5회}
quests:
  - {id: act1-desk-1, act: act1, week: 1, kind: desk, est_min: 20, text: 커리큘럼 정독 + 보고 포맷 세팅 + 첫 보고}
  - {id: act1-desk-2, act: act1, week: 1, kind: desk, est_min: 30, text: 안전 체크(소화기·배기·마스크·고글·장갑) + 장비 가이드 §4 재독}
  - {id: act1-desk-3, act: act1, week: 1, kind: desk, est_min: 30, text: 예시 시나리오 1개 읽고 STEP 흐름 익히기 + Streamlit 실행 연습}
  - {id: act1-lab-1,  act: act1, week: 1, kind: lab,  text: 저울 영점·교정, 정제수 10.000/50.00g 계량 연습, 온도·pH 측정}

```

## 7. 되먹임 — 커리큘럼 철학을 코드로

| 커리큘럼 장치 | 구현 |
|---|---|
| "오늘 뭘 할지 정해줄게요" | `next_quests` → 홈에 오늘 퀘스트 자동 |
| 10분의 법칙 | 결석 경고 + `DailyReport.ten_min` 체크로 출석 인정 |
| 결석 규칙(연속 2회 금지) | `days_since_report ≥ 2` → 복귀 경고 |
| 스트릭 카운트 | `streak()` 홈 표시 |
| 마일스톤 = 결과물 | act 완료 시 🏅 획득 표시 |
| 3줄 보고 | 보고 폼·로그, '내일 할 것' 자동 프리필 |
| 주간 회고 | 일요일 회고 리마인드 |

## 8. 원칙 정합

- **로컬 전용**, 데이터 2개 YAML. 영업비밀 아님(클라우드 불필요).
- **가벼움**: 홈 체크 1~2분. 무거운 분석·강제 진도 없음.
- `curriculum.yaml`은 **reference**(프로그램 정의). 사용자가 자기 리듬에 맞게 편집 가능.

## 9. 구현 순서 (작은 커밋)

1. 모델(Curriculum/Act/Quest/Milestone, Progress/DailyReport) + 로더 + `curriculum.yaml`(MD→변환, 5막 전체) + 빈 `progress.yaml` + 테스트(로드·검증).
2. `curriculum.py` 로직(next_quests·position·streak·days_since·milestone·prefill) + 테스트.
3. 상태 편집(set_start_date·toggle_quest·add_report·save) + 테스트(토글 후 다음 퀘스트 이동·보고 교체).
4. 홈 위젯 + AppTest.
5. 전용 페이지 `29_진행.py` + 사이드바 등록 + AppTest.
6. 문서 반영(홈 사용법에 '오늘·진행' 한 줄).

## 10. 테스트 계획

- `next_quests` 순서·kind 필터·n 제한, 완료 반영 후 다음으로 이동.
- `streak` 연속/공백, `days_since_report` 결석 감지.
- `milestone_status` act 완료 시 획득, 부분 진행률.
- `add_report` 같은 날짜 교체, `set_start_date` D+ 계산.
- 페이지 AppTest 무예외(빈 progress에서도 안전).

## 11. 범위 밖(후순위)

- 푸시/캘린더 연동, 자동 진도 강제, 통계·차트 고도화, 다중 커리큘럼. **지금은 리듬 유지만.**
