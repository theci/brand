# 설계안 — 시제품 관능·패널 평가 (Prototype Sensory / Panel Test)

> **한 줄:** 시제품(샘플)을 몇 명에게 나눠주고 **정량 피드백**을 받아 → **약점을 다음 버전에 반영**하고 → 강한 항목은 **근거 카드로 승격**하는, "프로토타입 → 피드백 → 반영" 루프의 빠진 조각.
>
> 상태: **✅ 구현 완료** (2026-09-04). 위치: STEP 5 · 실험·검증. 규제·수치는 예시(출시 전 확인).
>
> **구현 시 변경점:** 5의 `panel_edit.py`는 별도 파일 대신 기존 **`experiment_edit.py`** 에 합쳤다
> (DOE·안정성 편집과 같은 자리 — 사설 헬퍼 `_create`/`_dump` 재사용). 함수명은 설계와 동일
> (`panel_path`·`create_panel`·`set_panel_responses`). 시나리오 캡처는 S5-2·S5-3로 반영.

## 1. 왜 필요한가

지금 제품 피드백 경로는 둘뿐이고 **둘 다 어긋나** 있다:

- **DOE 점수**(STEP 5): 설계실험(요인×수준) 전용. "샘플 5개를 지인에게 주고 촉촉함 평가" 같은 일상 피드백엔 과하다.
- **출시 후 후기**(STEP 10): 이미 **MOQ를 찍은 뒤** — 반영하기엔 늦다.

정작 실무에서 OEM 샘플을 2~3라운드 돌리는 **"본생산 전 시제품 수용도 게이트"** 가 비어 있다. 이 기능이 그 자리를 채운다.

## 2. 기존 3가지와의 구분 (겹치지 않게)

| | 무엇을 | 언제 | 평가자 | 출력 |
|---|---|---|---|---|
| **DOE**(실험) | 처방 **인자 최적화**(무엇을 바꿀지) | 개발 초기 | 소수·내부 | 주효과·추천 조합 |
| **안정성**(실험) | 물리·미생물 **변질 여부** | 개발~시험 | 계측 | 관찰·판정 |
| **관능·패널**(신규) | 확정 후보 시제품의 **선호·수용도**(출시해도 되나/어느 버전이 이기나) | **본생산 직전** | **다수·타깃** | 항목 평균·약점·승자 |
| **후기**(고객접점) | 출시 후 **실사용** | 출시 후 | 실구매자 | 근거 카드 |

→ 관능·패널은 **DOE/안정성과 출시 사이**에 놓인다.

## 3. 데이터 모델 (`core/models.py`, `extra="forbid"`)

```python
class PanelResponse(BaseModel):
    model_config = ConfigDict(extra="forbid")
    panelist: str = Field(min_length=1)          # 이름/코드(익명화 가능)
    segment: str | None = None                   # 타깃/비타깃 — 필터·가중용
    scores: dict[str, float | None] = Field(default_factory=dict)  # 결측 허용(DoeRun과 동일)
    comment: str | None = None                   # 자유 코멘트(근거 인용 후보)

class PanelTest(BaseModel):
    model_config = ConfigDict(extra="forbid")
    test_id: str = Field(min_length=1)
    formula_ref: str | None = None               # "slug vN" — 어느 시제품
    sample_label: str | None = None              # 나눠준 시료 코드(로트/배치)
    test_date: date | None = None
    scale_max: int = 5                           # 척도 상한(기본 5점)
    attributes: list[str] = Field(min_length=1)  # 평가 항목
    targets: dict[str, float] | None = None      # 항목별 목표선(미달=약점)
    responses: list[PanelResponse] = Field(default_factory=list)
```

**저장 위치:** `experiments/panel/*.yaml` (doe·stability와 형제). 예시 파일 1개(`daily-lotion v2`)를 저장소에 포함해 시나리오와 연결.

```yaml
# experiments/panel/daily-lotion-v2-panel1.yaml
test_id: daily-lotion-v2-panel1
formula_ref: daily-lotion v2
sample_label: LOT-2026-03-A
test_date: 2026-03-10
scale_max: 5
attributes: [촉촉함, 산뜻함_비끈적, 향, 발림성, 재구매의사]
targets: {촉촉함: 4.0, 산뜻함_비끈적: 4.0, 재구매의사: 4.0}
responses:
  - {panelist: P1, segment: 타깃,  scores: {촉촉함: 4, 산뜻함_비끈적: 5, 향: 4, 발림성: 4, 재구매의사: 5}, comment: "오후에 덧발라도 안 밀려요."}
  - {panelist: P2, segment: 타깃,  scores: {촉촉함: 3, 산뜻함_비끈적: 4, 향: 3, 발림성: 4, 재구매의사: 4}, comment: "향이 살짝 약함."}
  - {panelist: P3, segment: 비타깃, scores: {촉촉함: 4, 산뜻함_비끈적: 4, 향: 5, 발림성: 5, 재구매의사: 4}, comment: ""}
```

## 6. UI — `pages/28_관능평가.py` (STEP 5 · 실험·검증)

`4_실험.py`가 이미 크므로 **새 페이지**로 분리. set_page_config 없음(entry에서 1회).

- **탭 ① 새 평가 생성**: `test_id`·`시제품(formula) 선택`·`평가 항목`(기본셋 체크 + 자유 추가)·`척도`·`목표선(targets)` → 저장(골격).
  - 기본 항목 프리셋(제형별): 로션=촉촉함·산뜻함·향·발림성·재구매의사.
- **탭 ② 응답 입력**: 평가 선택 → `st.data_editor`(행=평가자 dynamic, 열=segment·항목 점수·comment) → 저장.
  - **Arrow 주의**: 점수 열은 `NumberColumn`(정수/실수 고정)으로 문자 혼입 차단.
- **탭 ③ 요약·비교·근거**:
  - `summarize` → 항목별 **평균·top-box 막대** + **약점 배지**(목표 미달 빨강).
  - 세그먼트 토글(전체/타깃만).
  - 같은 slug 여러 버전 → `compare` 표(**항목별 승자 하이라이트**).
  - `improvement_hints` 목록(다음 버전 액션).
  - `panel_to_evidence` → 근거 카드 multiselect → **브랜드 코어 ⑤로 추가**(후기와 동일 UX).

## 7. 되먹임(핵심) — 어디로 흘러가나

- **약점 → 처방 개선**: `improvement_hints` → STEP 3(처방 새 버전)·STEP 5(버전비교)의 입력 근거. "감이 아니라 패널 숫자로 v3를 만든다."
- **강점 → 근거**: `panel_to_evidence` → 브랜드 코어 ⑤ 근거(=포지셔닝·마케팅 강화). 후기와 같은 승격 경로.
- **개발 서사(STEP 10)**: 관능 라운드가 타임라인 이벤트로("v2 패널 8명, 재구매의사 4.4") → Build in Public 콘텐츠 소재.
- **홈 대시보드 알림**: `응답 0건인 평가`(입력 미완료) / `약점 있는 시제품`(목표 미달) → risky_formula 알림과 동일 방식으로 연동.

## 8. 규제·주의 (설계에 못 박을 것)

- 관능은 **주관적·소표본** → 결과는 **내부 의사결정·참고용**(doe_optimize와 동일 톤). 효능·효과 표방 아님.
- 근거 카드를 **마케팅에 쓸 때**: "체험단 N명 관능 결과" 류는 실증 자료·표시광고 심사 대상일 수 있음 → **표본·방법 명시** + `compliance_check` 통과. 카드에 "※표본·방법 표기 필요" 자동 마킹.
- **대가성 체험단**이면 뒷광고 표기 — `touchpoints.INCENTIVE_DISCLOSURE` 재사용.

## 9. 구현 순서 (작은 커밋 단위)

1. 모델 `PanelTest`/`PanelResponse` + 로더 + 예시 YAML 1개 + 테스트(로드·검증).
2. `panel.py` `summarize`/`compare`/`improvement_hints` + 테스트(평균·top-box·결측·승자).
3. `panel_edit.py` 생성·저장 + 테스트(생성→재검증→롤백).
4. `panel_to_evidence` + 브랜드 코어 ⑤ 연동 + 테스트(임계값·마킹).
5. `pages/28_관능평가.py` + 사이드바 STEP 5 등록 + AppTest(무예외·응답 입력→요약).
6. 대시보드 알림 + 시나리오 문서(STEP 5에 캡처 S5-2/S5-3) 반영.

## 10. 테스트 계획

- 평균/top-box/결측 처리, 세그먼트 필터, 버전 비교 승자 판정.
- evidence 승격 임계값(min_mean·min_n)·대가성 마킹.
- 빈 응답·단일 평가자 안전(0-division 방지).
- 페이지 AppTest: 생성→응답 입력→요약 렌더 무예외.

## 11. 범위 밖(후순위, nice-to-have)

- 블라인드 시료 코드 자동 부여, 통계 유의성(t-검정), 코멘트 감성어휘 집계, 리커트 시각화 고도화.

---

> **사업 관점 연결:** 이 기능은 "제품력을 **숫자로** 증명"(뾰족함이 근거가 됨)하고, 그 숫자가 **포지셔닝·마케팅 근거**로 되먹여지며, **MOQ 쓰기 전에** 방향을 확정해 6:4 자본배분의 리스크를 줄인다. "싸게 많이 탐색 → 게이트 → 비싸게 한 번"의 **게이트**에 정확히 해당한다.
