# 플랫폼 확장 설계 — 상품 등록·마케팅까지 하나의 흐름

> **목적**: brand-lab(현재 STEP 1~8: 기획→개발→테스트→문서)을 확장해
> **기획 → 개발/테스트 → 공장 OEM → 상품 등록 → 마케팅** 을 한 흐름으로 만든다.
> 이 문서는 구현 전 **설계·로드맵**이며, 두 원천 문서를 반영한다:
> - `[나노바나나를 활용한 콘텐츠 제작 프로세스].txt` — 이미지 프롬프트 **6블록 구조 + 예시**
> - `나노바나나 핵심 프롬프트.xlsx` — 프롬프트 **키워드 팔레트**(Angle·Lighting·Texture·Color·Composition·Aesthetic)
> - `AI-마케팅-전략-가이드_1.md` — **브랜드 코어 시트 9칸** + 콘텐츠 공장 + 규제
>
> ⚠️ 모든 규제·수치는 예시. 집행 전 식약처·공정위 등 공식 출처 재확인.

---

## 0. 한 문장 결론

> **brand-lab = 제품의 Single Source of Truth.**
> 기획·개발·OEM 단계에서 쌓은 검증된 제품 데이터(전성분·함량·DOE·안정성·원가·공정·버전이력)가
> **그대로 상품 등록·마케팅 자산의 원천**이 된다. 남들은 빈 프롬프트에서 시작하지만, 우리는 데이터에서 시작한다.

마케팅 가이드가 못박은 두 가지 —
① "**근거(증거)가 화장품 브랜드의 승부처**"(성분 함량·시험 결과·제조 방식),
② "**AI에게 줄 브랜드 자산 문서를 먼저 만들라**" —
이 둘의 재료를 플랫폼이 이미 구조화된 데이터로 갖고 있다. 이 자산을 흘려보내는 것이 확장의 뼈대다.

## 1. 전체 라이프사이클 (STEP 1 ~ 10)

기존 STEP 1~8에 **STEP 9(상품 등록), STEP 10(마케팅)** 을 붙인다.

```
[STEP 1  기획·규제]   규제판정 — 무슨 법·비용
[STEP 2  원료·재료]   원료·포장재·재고
[STEP 3  처방·설계]   처방 생성/수정·사전점검(HLB)·조향
[STEP 4  제조·기록]   배치기록(수율·pH)
[STEP 5  실험·검증]   DOE·안정성·버전비교
[STEP 6  표시·검토]   라벨(전성분)·문구검사
[STEP 7  원가·구매]   손익·마진·장바구니
[STEP 8  문서]        제품표준서·공장 제출 패키지
        │  ← 공장 OEM (집=R&D, 생산=CGMP 위탁)
        ▼
[STEP 9  상품 등록]   상품명·상세페이지 텍스트·전성분 고지·옵션  ← NEW
        ▼
[STEP 10 마케팅]      브랜드 코어 시트·근거 카드·콘텐츠 팩·이미지 프롬프트·규제 검수  ← NEW
```

STEP 8까지의 데이터가 STEP 9·10의 **입력**이 된다는 것이 핵심. 마케팅은 제품과 단절된 별도 작업이 아니라 **데이터의 하류(downstream)** 다.

## 2. 두 원천 문서 ↔ 플랫폼 매핑

### 2-1. 브랜드 코어 시트 9칸 → 플랫폼 데이터 (마케팅 가이드 1부)

| 코어 시트 칸 | 채우는 방법 | 출처 |
|---|---|---|
| ① 카테고리 진입점 | 사람이 입력 | — |
| ② 타깃 (인물) | 사람이 입력 | — |
| ③ 적(반대하는 것) | 사람이 입력(가이드 예시 제공) | — |
| ④ 약속(한 문장) | 사람 + 템플릿 | — |
| ⑤ **근거 3가지** | **자동 초안** | 전성분·처방%·DOE·안정성·공정 (→ 모듈 B) |
| ⑥ 톤앤매너 | 사람 입력 + 금지어는 규제 데이터에서 | ad_terms.yaml |
| ⑦ **비주얼 코드** | 부분 자동 | 용기(packaging)·제형(formula)·컬러 |
| ⑧ **브랜드 어휘 사전** | 금지어 자동 + 애용어 사람 | ad_terms.yaml + 사람 |
| ⑨ 한 줄 소개 | 사람 + 템플릿 | — |

→ **⑤·⑦·⑧을 플랫폼이 자동 채운다.** 나머지는 사람 몫. 완성된 시트가 "브랜드 자산"으로 저장돼 모든 프롬프트 앞에 주입된다.

### 2-2. 나노바나나 프롬프트 = 6블록 구조(txt) + 키워드 팔레트(xlsx)

**txt의 6블록 구조** (모든 이미지 프롬프트의 뼈대):
```
[Subject]                    등장인물·제품·오브젝트
[Concept]                    콘셉트·주제
[Composition]                구도·시점
[Styling]                    헤어·메이크업·의상·질감
[Lighting & Background]      조명·배경·그림자
[Aesthetic & Brand Context]  브랜드 무드·레퍼런스·완성도
```

**xlsx의 키워드 팔레트** (각 블록을 채울 드롭다운 재료 — 6 카테고리 × 약 15개):
| 카테고리 | 예시 키워드(영/한) | 블록 대응 |
|---|---|---|
| **Angle** | top-down/탑뷰, low-angle/로우앵글, 45-degree, macro close-up, flat lay … | Composition |
| **Lighting** | soft diffused/소프트디퓨즈, backlight, rim light, natural daylight, warm/cool tone … | Lighting & Background |
| **Texture** | matte/글로시/velvet/metallic/woodgrain/clay … | Styling |
| **Color** | pastel/monochrome/neutral beige/icy blue/rosy pink/pure white … | Aesthetic·Background |
| **Composition** | minimal centered, floating object, product pedestal, rule of thirds, negative space … | Composition |
| **Aesthetic** | modern clean, luxury glossy, natural organic, editorial, soft feminine, dreamy pastel … | Aesthetic & Brand Context |

→ **설계 결론**: 프롬프트 빌더는 **6블록 폼**이고, Angle/Lighting/Texture/Color/Composition/Aesthetic 블록은 **xlsx 키워드를 드롭다운**으로 고른다. Subject/Concept는 **제품 데이터·코어 시트에서 자동 주입**. 최종 출력은 완성된 영어 프롬프트.

## 3. 신규 모듈 A ~ E (상세)

### A. 브랜드 코어 시트 (STEP 10 뿌리)
- **목적**: 마케팅의 모든 AI 프롬프트에 붙일 "브랜드 자산" 1장.
- **입력**: 제품(formula) 선택 + 사람 입력(진입점·타깃·적·약속·톤).
- **자동 채움**: ⑤근거(모듈 B), ⑦비주얼 코드(용기·제형·컬러), ⑧금지어(ad_terms.yaml).
- **출력/저장**: `brand/core.yaml` (제품/브랜드 단위). "자산 텍스트 내보내기" 버튼 → 프롬프트 머리말로 복사.
- **재사용 코드**: labeling(전성분), regulatory ad_terms.

### B. 근거(Evidence) 카드 — 검증된 클레임 재료
- **목적**: 지어내지 않고 **데이터에서 나온 사실**만으로 마케팅 문장 재료를 만든다(규제 안전).
- **자동 추출 예** (basic-lotion v2):
  - "정제수 기반 O/W, 유화제 2종으로 HLB 균형" (사전점검)
  - "스쿠알란·시어버터 등 유상 14% 배합" (처방 — %만, 전체 처방은 비공개)
  - "45℃ 8주 안정성 관찰 통과" (안정성)
  - "v1 층분리 → v2 개선" (버전 이력 = 가이드 12포맷의 '실패담·비하인드')
- **출력**: 근거 카드 목록(문장 + 출처 태그). 코어 시트 ⑤와 콘텐츠 팩(모듈 C·D)에 주입.
- **★영업비밀 보호**: 전체 처방 %는 노출 금지. "근거 문장"만 뽑고, 민감 수치는 마스킹 옵션.

### C. 상세페이지·리스팅 생성기 (STEP 9)
- **목적**: 피그마 상세페이지 템플릿에 넣을 **텍스트 블록** + 커머스 리스팅 필드 생성.
- **출력**:
  - 상품명 후보 / 한 줄 소개 / 상세페이지 블록(헤드라인+본문) / **전성분 고지**(라벨에서) / 사용법 / 주의사항 / 옵션·용량.
  - **이미지는 실촬영 필수** → 플랫폼은 "**필요 촬영 컷 리스트**(정면·측면·45°·제형 클로즈업·사용컷)" + "배경만 교체할 AI 프롬프트"를 함께 제공.
- **재사용 코드**: dossier(제품표준서)·labeling(전성분)·factory_package 패턴.
- **출력물 저장**: `listings/<slug>.md`.

### D. 나노바나나 이미지 프롬프트 빌더 (STEP 10)
- **목적**: txt 6블록 × xlsx 키워드로 완성도 높은 영어 프롬프트를 생성·관리.
- **UI**:
  1. 제품 선택 → [Subject]/[Concept] 자동 초안(용기=packaging, 제형=formula, 무드=코어시트 ⑦).
  2. Angle·Lighting·Texture·Color·Composition·Aesthetic → **xlsx 키워드 드롭다운**(다중 선택).
  3. "프롬프트 생성" → 6블록 영어 프롬프트 조립 출력(복사용).
- **프롬프트 라이브러리**: txt의 완성 예시(각도컷·원료 시각화·제형·발색·상세페이지 비주얼·모델컷)를 **카테고리별 프리셋**으로 저장·재사용.
- **키워드 라이브러리 저장**: `marketing/prompt_keywords.yaml` (xlsx를 YAML로 이관 → UI 드롭다운 소스).
- **★실촬영 강제(코드)**: 제품이 주체인 프롬프트에는 자동으로 다음을 삽입 —
  `"Use the uploaded real product photo as reference; keep exact shape/color/texture. AI generates only background & mood, never the product formula/texture."`
  (txt 5-3·6-1의 "제형·발림·색은 실촬영 필수" 규칙을 기계적으로 보장.)

### E. 규제 검수 게이트 — 기존 문구검사 확장 ⭐ 킬러 기능
- **목적**: 생성된 **모든 마케팅 텍스트**(상세페이지·카피·블로그·광고·캡션)를 출고 전 통과.
- **검사 항목**:
  - 화장품법 금지·주의 표현(치료·미백·주름개선·최상급 등 — 이미 ad_terms.yaml/문구검사 보유).
  - **브랜드 어휘 사전 금지어**(코어 시트 ⑧) 추가 룰.
  - **뒷광고 표기**(가이드 8·14부): 협찬/광고 표기 위치·문구 체크리스트.
- **재사용 코드**: `adcopy`/`6_문구검사` 그대로 + 룰 소스 확장.
- **동선**: 모듈 C·D 출력에 "검수 통과" 배지가 붙어야 내보내기 가능(게이트).

## 4. 데이터 모델 (YAML 스키마 초안)

지금 원칙(로직=src/brandlab, UI=표시, 데이터=YAML) 그대로 확장한다.

```
brand/core.yaml                  # 브랜드 코어 시트 9칸(제품/브랜드 단위)
marketing/prompt_keywords.yaml   # xlsx 키워드 팔레트(6 카테고리)
marketing/prompts/*.yaml         # 프롬프트 라이브러리(프리셋 + 저장한 것)
listings/<slug>.md               # 상세페이지·리스팅 텍스트 산출물
```

`prompt_keywords.yaml` (xlsx 이관 예):
```yaml
angle:
  - {en: top-down, ko: 탑뷰 각도, hint: "Top-down product shot on clean background"}
  - {en: low-angle, ko: 로우앵글, hint: "Heroic low-angle emphasizing silhouette"}
lighting:
  - {en: soft diffused, ko: 소프트 디퓨즈, hint: "Soft minimal shadow lighting"}
# texture / color / composition / aesthetic ... (xlsx 106행 그대로 이관)
```

`core.yaml` (요지):
```yaml
brand_name: ...
product_ref: basic-lotion v2
entry_points: [환절기 볼 붉어짐, ...]     # ①
persona: "성분표를 검색해보고 사는 사람 ..."  # ②
enemy: "성분 0.001%에 이름만 앞세우는 마케팅"  # ③
promise: "..."                              # ④
evidence: [자동 생성 카드 id ...]            # ⑤ ← 모듈 B
tone: {adjectives: [담백한, 근거있는], forbidden: [최고, 인생템]}  # ⑥⑧
visual: {main_color: "#...", container: 유리자, texture: 로션}     # ⑦
one_liner: "..."                            # ⑨
```

## 5. 규제·안전 설계 (플랫폼의 차별점)

1인 창업자가 가장 무서워하는 게 규제다. 플랫폼이 이걸 **코드로 방어**하는 게 최대 차별점.

- **실촬영 강제**: 제품 실물(형태·색·제형)은 AI 생성 금지 문구를 프롬프트에 자동 삽입(모듈 D).
- **규제 검수 게이트**: 모든 마케팅 텍스트는 문구검사 통과 후에만 내보내기(모듈 E).
- **근거 기반 클레임만**: 마케팅 문장은 데이터 근거 카드에서만 파생(모듈 B). 근거 없는 효능 단정 차단.
- **영업비밀 보호**: 전체 처방 % 비공개. 근거 문장·전성분만 외부로.
- **뒷광고 표기 가드**: 체험단/협찬 콘텐츠에 표기 위치·문구 체크리스트 강제.

## 6. 아키텍처 원칙

1. **LLM은 처음엔 부르지 않는다.** 플랫폼은 "**완성된 프롬프트 + 브랜드 자산**"을 **생성**만 하고, 사용자가 ChatGPT/Gemini/나노바나나에 붙여넣기. → 비용 0·안전·현 구조와 일관.
2. **나중에 자동화(Phase 4)**: 원하면 Claude API 직접 연동으로 "붙여넣기" 단계를 없앰(카피 자동 생성). 이미지는 여전히 실촬영 원칙 유지.
3. **데이터는 YAML**, 산출물은 md/txt로 내보내기. Git 버전관리.
4. **기존 자산 재사용**: 전성분(labeling), 규제표현(ad_terms/문구검사), 제품표준서(dossier), 패키지(factory_package) — 새로 만들지 말고 잇는다.

## 7. 로드맵 (Phase 1 ~ 4)

| Phase | 모듈 | 산출물 | 왜 이 순서 |
|---|---|---|---|
| **1** | A·B | 브랜드 코어 시트 + 근거 카드 (`core.yaml`) | 가이드가 "여기부터". 모든 프롬프트의 뿌리 |
| **2** | C·E | 상세페이지/리스팅 생성 + 규제 검수 게이트 | 상품 등록 다리 + 규제 방어(킬러) |
| **3** | D | 나노바나나 프롬프트 빌더 + 키워드 라이브러리(xlsx 이관) | 이미지 자산 → 피그마 템플릿 연결 |
| **4** | (선택) | LLM API 직접 연동 | 붙여넣기 → 자동 생성 |

## 8. 리스크·주의

- **AI 생성 이미지의 제품 왜곡** = 허위·과장 광고 리스크. → 실촬영 강제(§5)로 방어하되, 최종 책임은 사람 검수.
- **규제 데이터 최신성**: ad_terms.yaml·화장품법 표현은 계속 바뀜. last_updated·source_url 유지, 주기적 갱신.
- **뒷광고·표시광고법**: 표기 누락은 브랜드에 치명적. 게이트는 보조일 뿐, 최종 확인은 사람.
- **플랫폼 과확장 경계**: 마케팅 실행(발행·광고 집행)까지 플랫폼이 다 하려 하지 말 것. 플랫폼은 **"자산·프롬프트·검수"의 원천**에 집중하고, 발행은 각 채널 도구에 맡긴다.

## 9. 요약

- 이 플랫폼의 진짜 힘은 **검증된 제품 데이터(근거)를 이미 갖고 있다는 것.**
- 확장의 방향은 그 데이터를 **상품 등록·마케팅 자산으로 흘려보내는 파이프**를 놓는 것.
- 두 원천 문서는 이렇게 맞물린다: **브랜드 코어 시트(자산) → 근거 카드(재료) → 상세페이지/프롬프트(생성) → 규제 검수(게이트)**.
- 나노바나나는 **6블록 구조(txt) + 키워드 팔레트(xlsx)** 를 폼·드롭다운으로 구현하고, 제품 데이터를 자동 주입한다.
- **Phase 1(브랜드 코어 시트 + 근거 카드)부터** 시작한다.

> ⚠️ 본 문서의 규제·표현·수치는 예시이며 법적 자문이 아니다. 집행 전 식약처·공정위·각 채널 정책을 반드시 확인하라.
