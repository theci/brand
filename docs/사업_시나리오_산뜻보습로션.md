# 사업 전 과정 쉐도잉 — "오후 산뜻 보습 로션" (칸 단위 실습판)

> **이 문서는 무엇인가**
> 플랫폼을 **처음 켠 사람**이 화면을 보고 "이 칸에 뭘 넣지? 어느 버튼을 누르지?"를 헤매지 않도록,
> 제품 하나를 **기획→개발→검증→디자인→마케팅→고객·후기→자금**까지 끌고 가는 전 과정을
> **① 사고의 흐름 → ② 화면에서 입력할 값(칸별) → ③ 누를 버튼 → ④ 나오는 결과** 로 적었습니다.
>
> 숫자는 저장소 예시 데이터로 **실제 실행한 값**입니다. 규제·수치는 1차 스크리닝(출시 전 관할기관 확인 필요).

**보는 법**: 왼쪽 사이드바는 **STEP 0~11 순서**. 위에서 아래로 따라가세요. 각 페이지에서 값을 채우고 저장한 뒤 **새로고침(F5)** 하면 반영됩니다.

**주인공/제품**: 1인 창업자 박수민 · 브랜드 **오후(OHU)** · 제품 **"오후 산뜻 보습 로션"**(50mL, 화장품).
**한 줄**: 냉난방 사무실에서 오후만 되면 당기는 피부를 위한, 끈적이지 않는 지속 보습 로션.

> 표 기호: **[버튼]** = 클릭할 버튼, `칸 이름` = 화면의 입력 칸, → = 결과.

# STEP 0 · 기획 — 누구의 무슨 문제를 풀지부터

## 0-1. `페르소나 · JTBD` 페이지 🧑

> 🧭 **사고의 흐름:** "수분크림 만들까?"가 아니라 **"누가, 언제, 뭘 불편해하나"** 를 먼저 적는다. 페인을 점수로 매겨 **1순위 하나**를 고른다.

**① 페르소나 표에 한 줄 입력** (표에서 행을 채웁니다):

| 칸 | 넣을 값(예시) | 왜 |
|---|---|---|
| `id` | `dry-office-30s` | 영문·하이픈 고유 이름표(다른 표가 이걸로 연결) |
| `name` | `건조한 사무직 30대` | 사람이 읽는 이름 |
| `one_line` | `냉난방 사무실에서 하루 종일 당김을 느끼는 30대 직장인` | 한 줄 정의(포지셔닝 '타깃'으로 그대로 감) |
| `context` | `실내 근무 8시간, 냉난방 상시, 점심 후 화장 들뜸` | 상황 |
| `jobs(쉼표)` | `바쁜 아침 빠른 흡수, 메이크업 위 덧바름` | 고객이 시키는 일(JTBD) |
| `current_solution` | `대형 브랜드 수분크림` | 지금 쓰는 대안 |
| `dissatisfaction` | `끈적이고 흡수가 느려 화장이 밀림` | 그 대안의 불만(문제의 씨앗) |
| `priority` | `5` | 타깃 우선순위(1~5) |

**② 페인 표에 두 줄 입력** (`persona_id`로 위 페르소나에 연결):

| persona_id | desc | severity | frequency |
|---|---|---|---|
| `dry-office-30s` | `오후만 되면 볼이 당기고 각질이 인다` | `5` | `4` |
| `dry-office-30s` | `수분크림이 끈적여 덧바르기 싫다` | `3` | `4` |

▶️ **[💾 페르소나 저장]** → 새로고침 → 상단 **🔥 페인 우선순위** 표:
- 오후 당김 **점수 20**(5×4), 끈적임 12 → **1순위 = 오후 당김**

> 💡 **결정:** 감이 아니라 **점수 20**으로 "이것부터 푼다"가 정해진다. severity·frequency는 1~5로 솔직하게. (근거가 있으면 `source_ref`에 다음 페이지의 출처 id를 적는다.)

> 💡 **결정:** 진짜 문제는 "보습 부족"이 아니라 **"끈적여서 덧바를 수 없음"**. → 해결책이 "더 강한 보습"이 아니라 **"산뜻한 지속 보습"** 으로 갈린다. 방향이 여기서 결정된다.

> 💡 **결정:** `CAS`·`밀도`는 손으로 안 찾는다(자동). **붉은 행(CoA 없음/화장품용 아님)** 원료는 그대로 쓰지 않는다.

# STEP 5 · 실험·검증 — v1을 v2로, 원가 영향 확인

## 7-2. `장바구니` 페이지 🛒

▶️ `처방 선택`=daily-lotion v2, `구매 기준`=`생산 수량(개)`, `생산 수량`=`1000`:
→ **총 예상 구매액 2,874,542원** = 원료 474,542 + **포장 2,400,000**.

> 💡 **결정:** 비용 대부분이 **용기 MOQ(3,000개)** — 1,000개만 필요한데 3,000개 사야 해 **2,000개 사장 재고**. **병목은 처방이 아니라 포장.** → 용기 업체 재검토 or 초도 물량 상향 저울질.

## 7-3. `자금 6:4` 페이지 🏦

|---|---|
| `총 자본(원)` | `10000000` |

# STEP 9 · 디자인 — 패키지·라벨 (규격 먼저)

> 🧭 **순서 주의:** 패키지·라벨은 **제품 규격을 먼저 봐야** 한다 — 내용량(50mL)·용기 규격(용량·재질)·라벨 **법정 필수기재**. 이 규격들은 STEP 2(포장재)·3(처방)·6(라벨)·7(용기 확정, MOQ)에서 정해지고, **디자인 브리프가 그걸 자동으로 모아준다.** 그래서 디자인 브리프가 곧 "규격을 먼저 본" 단계이고, 규격이 확정된 **뒤(STEP 9)** 에 온다.

## `디자인 브리프` 페이지 🎨

`처방 선택`=daily-lotion v2 → **[디자인 브리프 내려받기(.md)]**. 브리프에 자동 포함:
- **규격** — 내용량·용기 규격(용량·재질)
- **규제** — 라벨 법정 필수기재 체크리스트 + 전성분 표시(안)
- **톤** — 기획의 페르소나·문제 + 브랜드 비주얼(컬러·사진 톤·금지어)

브리프 하단 **§6에 "패키지·라벨 아트 프롬프트"가 자동 생성**됩니다(규격·컬러·톤·필수기재 여백·금지어 반영). 이걸 복사해 **① 이미지 생성 → ② 일러스트레이터(벡터·인쇄)** 로 패키지/라벨을 만든다.

> 💡 **결정:** 상세페이지(STEP 10)와 **원리는 같다**(프롬프트→이미지→편집툴). 도구·목적만 다르다.
> - **패키지·라벨** = 규격·인쇄 중심 → **일러스트레이터(벡터)**
> - **상세페이지** = 화면·마케팅 중심 → **피그마**
>
> 규격을 확정하지 않고 디자인부터 하면 **라벨 필수기재 누락·용기 안 맞음** 등 재작업이 난다. 그래서 규격(브리프)이 먼저.

# STEP 10 · 마케팅·등록

> 🧭 **순서 주의(중요):** 상세페이지를 만들려면 **이미지가 먼저** 필요하다. 그래서 흐름은
> **① 이미지 프롬프트(소재) → ② 이미지 생성 → ③ 피그마 상세페이지 → ④ 상품 등록(리스팅)**.
> 그래서 **상품 등록은 이미지 프롬프트 뒤**에 온다.

## `개발 서사` 페이지 🎬
v1→v2 개선·배치·실험 기록이 **타임라인·콘텐츠 소재**로("묽음 잡으려 잔탄검 올린 이야기" = 비하인드).

## `이미지 프롬프트` 페이지 🖼️
제품·브랜드 톤(브랜드 코어 ⑦ 비주얼)으로 상세페이지·SNS용 **이미지 생성 프롬프트**를 만든다 → 그 프롬프트로 이미지 생성 → **피그마에서 상세페이지 제작**.

> 💡 **결정:** 브랜드 코어의 컬러·사진 톤·금지어가 프롬프트에 반영돼 **일관된 비주얼**. 실사가 필요한 부분은 실촬영 안내가 붙는다.

## `상품 등록` 페이지 📝
위에서 만든 **상세페이지가 완성된 뒤** 리스팅 자료 생성 → 규제 검수 게이트 통과 → 스마트스토어 등에 등록.

> 💡 **결정:** 등록은 이미지·상세페이지가 준비된 **뒤**. 이미지 프롬프트(소재)가 상품 등록의 선행이라 순서가 이렇게 된다.

## `고객 접점 · 후기` 페이지 💬

`제품 선택`=오후 산뜻 보습 로션 → 탭별로:
- **동봉 카드** 탭: 문구 자동 생성 → 아래 **규제 게이트 ✅ 통과** 확인
- **후기 요청** 탭: `대가성(협찬·원고료)` 체크하면 **뒷광고 표기 문구 자동 첨부**
- **재구매 시나리오** 탭: **D+3 / 14 / 40 / 70** 메시지
- **후기 → 증거** 탭: ★4↑·구매확인 후기가 **근거 카드로 승격**

> 💡 **결정:** 협찬 후기엔 반드시 "협찬" 표기 — **시스템이 강제**하므로 실수 없음.
