# 플랫폼 확장 설계 — 사업화 로드맵 (포지셔닝·서사·인증·디자인·고객접점·자금)

> **이 문서는 무엇인가**
> 원료→개발→테스트→공장(OEM)→디자인→상품등록→마케팅→배송→소비자까지, 1인 창업자의
> 전체 여정에서 지금 플랫폼(STEP 1~10)에 **빠진 조각**을 Phase로 설계한다.
> 마케팅 Phase 1~4(`플랫폼_확장_마케팅_설계.md`)에 이어지는 **사업화 단계(Phase 5~10)**.
>
> **작성 맥락**: 회사 노트북으로 옮겨 작업 지속 예정 → §7 '내일 시작 가이드'에 환경 재현법 포함.
> ⚠️ 규제·수치·관문은 예시. 집행 전 식약처·환경부·공정위 등 공식 출처 재확인 필수.

## 0. 창업자 철학 = 설계 원칙

이 확장은 창업자가 정리한 철학을 **도구로 번역**하는 것이다.

| 철학 | 도구화 (어느 Phase) |
|---|---|
| **개발 전 기획 우선** · 고객·문제 발견(페르소나·페인·시장/경쟁 조사) = 뾰족함의 재료 | **Phase 11 기획(Discovery)** ⭐ 상류 |
| 제품력의 시대 · **뾰족함** · 작은 시장 1등 · 포지셔닝 | **Phase 5 포지셔닝 엔진** |
| Build in Public · **못 베끼는 서사** · 기술 팬덤 | **Phase 6 개발 서사** |
| 마케팅은 결국 제품력으로 수렴(증거) | (이미 구현: 근거 카드) + Phase 9 후기=증거 |
| 마케팅 = 고객과의 대화 | Phase 9 고객 접점 |
| 자본 6:4 배분 | Phase 10 자금 대시보드 |
| 상황과 제품 연결(카테고리 진입점) | Phase 5·브랜드 코어 |

**플랫폼 정체성(불변)**: 이 플랫폼은 **"증거·서사·포지셔닝의 원천"** 이다. 커머스 운영(배송·결제·CS)은 하지 않는다(§6).

**아키텍처 원칙(불변)**: 로직=`src/brandlab`, UI=표시, 데이터=YAML(pydantic `extra="forbid"`), LLM은 프롬프트 생성 후 붙여넣기(자동화는 선택), 규제·실촬영은 코드로 강제, 처방 %는 영업비밀.

## ✳ Phase 11 — 기획(Discovery) ⭐ 새 최상류 (Phase 5의 상류)  ✅ 구현됨

**왜 새로 만드나**: 지금은 페르소나·페인이 `Positioning`·`BrandCore`의 **문자열 한 칸**에 압축돼 있다. 시장조사·자료조사가 쌓이면 터진다. "제품 개발 전에 기획(고객·문제 발견)이 먼저"라는 원칙을, 리서치가 쌓여도 안 깨지는 **데이터 레이어**로 정식화한다.

**정체성 확장**: 플랫폼 = *"증거·서사·포지셔닝의 원천"* → 여기에 상류로 **"고객·문제의 원천(Discovery)"** 을 얹는다.
> 흐름: **고객·문제 발견(Phase 11) → 포지셔닝 뾰족함(Phase 5) → 제품력 증거 → 서사(Phase 6)**

**설계 원칙(확장성 3계명)**:
1. 조사 산출물마다 **독립 파일 + 독립 모델** → 나중에 항목(인터뷰·트렌드 등) 추가해도 기존 불변.
2. **출처(ResearchSource)를 1급 객체** → 모든 수치·주장이 출처를 달도록(규제 데이터의 `source_url` 철학과 동일).
3. 기획 결과를 **하류로 자동 주입(프리필)** → 리서치를 더 할수록 포지셔닝·브랜드코어·디자인브리프가 저절로 좋아진다.

### 사이드바 재구성 — STEP 0을 "기획"으로 확대
```
STEP 0 · 기획 (Discovery)
  ├─ 페르소나 · JTBD        (신규)
  ├─ 시장 · 경쟁 조사        (신규)  ← 리서치 노트 + 경쟁표 + 출처
  ├─ 문제 정의              (신규)  ← 위 둘을 종합
  ├─ 포지셔닝               (기존 pages/19, 여기로)
  └─ 브랜드 코어            (기존 pages/16, STEP 10 → 여기로 ★순서 모순 교정)
```
※ `브랜드 코어`는 포지셔닝의 **입력**(타깃·적)이면서 지금 STEP 10에 있는 순서 모순 → STEP 0으로 상향. 개발 서사·이미지 프롬프트는 STEP 10 유지(산출물이므로).

### 데이터/모델 (`data/brand/` — 파일 분리 = 확장 지점)
| 파일 | 모델 | 필드(전부 선택, 부분 저장) |
|---|---|---|
| `personas.yaml` | `Persona[]` | `id, name, one_line, context, jobs[], current_solution, dissatisfaction, priority, pains[]` |
| (persona.pains) | `PainPoint[]` | `desc, severity(1~5), frequency(1~5), source_ref` · 점수=severity×frequency |
| `research.yaml` | `ResearchSource[]` | `id, title, url, kind(기사/논문/리뷰/규정/데이터), date, reliability(1~5)` |
| | `MarketNote[]` | `topic, summary, metric, tags[](트렌드/규모/가격/규제), source_ref` |
| | `Competitor[]` | `name(현상·실명지양), category, price_band, claims[], strengths[], gaps[], source_ref` |
| `problem.yaml` | `ProblemStatement` | `persona_ref, core_pain, statement, hypothesis, success_metric` |

`core/models.py`에 위 모델 추가(전부 `extra="forbid"`, 필드 선택). `PainPoint.score` = 계산 프로퍼티.

### 모듈 `src/brandlab/discovery.py`
- `rank_pains(personas) -> list[PainPoint]` — severity×frequency 내림차순
- `draft_problem_statement(persona, pains) -> str` — 문제 문장 자동 초안
- `to_positioning_inputs(discovery) -> dict` — 페르소나→`target`, 최우선 페인→`pain`, 경쟁 `gaps`→`comparison[]`. **포지셔닝 페이지가 프리필로 당겨씀**
- `to_brandcore_inputs(discovery) -> dict` — persona→`persona`, competitor→`enemy`, jobs→`entry_points`
- `load_discovery` / `save_*`(loader) — personas·research·problem 각각

### 하류 연결 (자동 품질 향상)
- **포지셔닝**: `to_positioning_inputs`로 target/pain/comparison 프리필(재입력 제거)
- **브랜드 코어**: persona/enemy 프리필
- **디자인 브리프(Phase 8)**: 페르소나·톤을 그대로 물고 나옴 → *기획을 먼저 해야 브리프 품질이 오른다*
- **홈 대시보드**: "기획 미완(페르소나 0 / 문제정의 없음)" 알림 추가 가능

### 스코프 경계 (1인 창업 — 과하지 않게)
- ❌ 대규모 설문·정밀 TAM/SAM/SOM·실시간 크롤링 (외부 도구·엑셀 영역)
- ✅ 리서치를 **구조화해 쌓고, 하류로 흘려보내는 것**에만 집중 (플랫폼 정체성과 동일)

### 착수 산출물 (커밋 단위)
1. ✅ 모델 6종(`Persona/PainPoint/ResearchSource/MarketNote/Competitor/ProblemStatement`) + `Discovery` 묶음 + `load_discovery` + `data/brand/`(personas·research·problem) 예시 + `test_discovery.py`(7종). *(주의: 필드명 `date`는 타입을 가려 `researched_on` 사용.)*
2. ✅ `discovery.py`(`rank_pains`·`primary_persona`·`top_pain`·`draft_problem_statement`·`to_positioning_inputs`·`to_brandcore_inputs`·`save_*`) + 테스트 14종.
3. ✅ 페이지 3종: `pages/25_페르소나.py`(랭킹·페인 편집) · `pages/26_시장경쟁조사.py`(출처·노트·경쟁 편집+무결성 경고) · `pages/27_문제정의.py`(자동초안+프리필 미리보기) → 사이드바 `STEP 0 · 기획·전략`에 등록. AppTest 통과.
4. ✅ 사이드바 `STEP 0 · 기획·전략` 재구성 — 브랜드 코어를 STEP 10→STEP 0으로 이동, 포지셔닝·브랜드코어에 **"기획에서 프리필(빈 칸만)" 버튼** 연결(포지셔닝=모델 병합, 브랜드코어=session_state). AppTest로 프리필 동작까지 검증.
5. ✅ AppTest(페이지 6종·프리필 클릭) + 전체 322 passed. *(홈 대시보드 '기획 미완' 알림은 선택 — 추후.)*

**노력**: 중간 · 효과: 최상류(모든 하류 품질↑). **선행 조건 없음**(오히려 Phase 8의 선행이 되는 게 이상적).

## 2. Phase 5 — 포지셔닝 엔진 ⭐ 최우선  ✅ 구현됨

**목적**: "뾰족함"을 강제해 포지셔닝 문장을 자동 조립. 모든 STEP의 상류(뿌리).
**철학**: 제품력의 시대·포지셔닝·작은 시장 1등.
**한 문장 목표**: 창업자가 쓴 이 문장을 데이터로 완성한다 —
> *우리는 [타겟]에게 [경쟁]이 못 푼 [페인]을 [신물질/공정]으로 [수치적 이익]으로 해결하는 유일한 [카테고리]다.*

**입력(재사용)**: `evidence_cards`(수치 우위 원천) · 브랜드 코어(타겟·적) · 처방/DOE(신공정 근거).
**산출물(UI)**:
- 경쟁 비교표 입력(축별: 우리 값 vs 기존/경쟁 값 → 우위 자동 표시)
- 수치적 차별점 카드(제품 데이터 + 경쟁 대비, 예: "스쿠알란 9% vs 통상 1%")
- 카테고리 진입점(상황) 정의 → 브랜드 코어 ①로 연결
- **포지셔닝 문장 자동 조립** + 대안 3안
- 저장 → 브랜드 코어의 ③적·④약속 강화 주입

**데이터/모델**: `data/brand/positioning.yaml`
```
target, pain, competitor, competitor_gap, tech(신물질/공정),
metric_benefit, category, entry_situations[], 
comparison[]: {axis, ours, theirs, ours_wins: bool}
```
`core/models.py`에 `Positioning`(전 필드 선택), `ComparisonRow`.

**모듈**: `src/brandlab/positioning.py`
- `build_statement(pos) -> str` (+ `variants` 3안)
- `suggest_metrics(formula, lab) -> list[str]` (evidence 기반 수치 우위 후보)
- `save_positioning` / `load_positioning`(loader)

**페이지**: `pages/19_포지셔닝.py` → 사이드바 **"STEP 0 · 전략"**(홈 다음, 최상단). 포지셔닝이 모든 것보다 앞.

**테스트**: 문장 조립(빈 칸 처리)·suggest_metrics가 evidence에서 추출·비교표 우위 판정·저장 왕복.

**착수 산출물(내일 첫 커밋 단위)**:
1. `Positioning`·`ComparisonRow` 모델 + `load_positioning`.
2. `positioning.py`(build_statement/variants/suggest_metrics/save).
3. `tests/test_positioning.py`.
4. `pages/19_포지셔닝.py` + STEP 0 섹션(streamlit_app.py).
5. AppTest + 전체 테스트.

## 3. Phase 6 — 개발 서사 / Build-in-Public 🥈  ✅ 구현됨
> 구현: `src/brandlab/narrative.py`(timeline·content_seeds·seed_to_prompt),
> `pages/20_개발서사.py`(STEP 10). 버전·배치·DOE·안정성에서 타임라인·12포맷 소재 생성.

**목적**: 흩어진 개발 기록을 **서사·콘텐츠 소재**로. "제품은 베껴도 서사는 못 베낀다."
**철학**: Build in Public·기술 팬덤.
**입력(재사용, 이미 다 있음)**: 배치기록·버전이력(v1→v2)·DOE·안정성·사전점검(위험→개선).
**산출물**:
- 제품 **개발 타임라인**(날짜순 이벤트: 배치·버전·실험·실패·개선)
- **콘텐츠 소재 카드** → 마케팅 12포맷 매핑(실패담·비하인드·성분해부)
- 각 소재 → 게시 프롬프트(브랜드 자산 주입 + 규제 준수 + 실촬영 안내)
**데이터/모델**: 대부분 파생(새 저장 최소). 선택: `data/brand/journal.yaml`(창업자 메모).
**모듈**: `src/brandlab/narrative.py` — `timeline(slug, lab, batches, doe, stability)`, `content_seeds(...)`, `seed_to_prompt(seed, core)`.

## 6. 만들지 않을 것 (스코프 경계 — 중요)

- **실제 배송·주문·결제·CS·재고 판매관리** → 스마트스토어·쿠팡·Shopify. 플랫폼이 손대면 정체성이 흐려진다.
- **패키지/라벨 그래픽 디자인 툴** → 피그마·외주. 플랫폼은 **브리프(사양)** 까지만.
- **회계·세무** → 외부. 플랫폼은 **원가·자금 배분 시야**까지만.
- 플랫폼의 대체 불가능한 정체성 = **증거·서사·포지셔닝의 원천**. 여기에 집중.

```
        └──────────────────────┬──────────────────────┘
              Phase 8 디자인 · 9 고객접점 · 10 자금  (병렬 가능)
```
**다음 착수: Phase 11 기획(Discovery)** — Phase 5(포지셔닝)의 상류이자 Phase 8(디자인 브리프)의 선행. 기획을 데이터화하면 하류 전부(포지셔닝·브랜드코어·브리프)가 프리필로 좋아진다. Phase 5·6·7은 이미 구현됨.

### 내일(회사 노트북) 환경 재현
```powershell
# 1) 코드 받기
git clone https://github.com/theci/brand.git   # 또는 git pull
cd brand

# 2) 검증용 가상환경 (노트북마다 새로 생성 — .venv_verify는 .gitignore됨)
python -m venv .venv_verify
.\.venv_verify\Scripts\python.exe -m pip install -q pydantic pyyaml pytest streamlit matplotlib openpyxl anthropic

# 3) 앱 실행
$env:PYTHONPATH = "src"; $env:PYTHONIOENCODING = "utf-8"
.\.venv_verify\Scripts\streamlit.exe run streamlit_app.py

# 4) 테스트 (pytest 콘솔 출력이 툴과 충돌하면 junit 러너로 요약만)
.\.venv_verify\Scripts\python.exe -m pytest -q
```
> 데이터·코드는 전부 git으로 이동한다. **가상환경만 노트북마다 새로 만든다.**
> `data/brand/`·`listings/`·`.venv_verify/`는 gitignore이거나 로컬 산출물이니, 없으면 화면에서 생성된다.

### 개발 리듬(이 프로젝트에서 확립된 방식)
- **로직 모듈 + 테스트 → 페이지 → AppTest → 증분 커밋**.
- 각 Phase는 위 '착수 산출물'을 1~2 커밋으로.
- 커밋 메시지 끝: `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>` / `Claude-Session: ...`.

## 8. 요약

- 플랫폼은 **제품력(증거)**을 이미 완성했다. 남은 건 창업자 철학의 나머지 절반 — **기획(고객·문제 발견)·뾰족함(포지셔닝)·못 베끼는 서사**.
- **Phase 11 기획(Discovery)** 이 새 최상류. 개발 전 기획 우선 원칙을 데이터화해 하류(포지셔닝·브랜드코어·디자인브리프)를 프리필로 끌어올린다.
- Phase 5(포지셔닝) → 6(서사) → 7(인증)은 구현 완료, 8·9·10은 보강, **11이 그 위 상류**.
- 커머스 운영은 외부에 맡기고, 플랫폼은 **고객·문제 + 증거·서사·포지셔닝의 원천**에 집중한다.
- **다음 착수: Phase 11 기획.** 착수 산출물·환경 재현법은 위에.
