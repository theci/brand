# 실습 01 — 라벤더 리드 디퓨저 (초보자 첫 제품)

> **이 문서의 목표**
> brand-lab **화면(Streamlit UI)만 클릭해서**, 초보자가 제품 하나를 처음부터 끝까지 굴려봅니다.
> 만들 제품: **라벤더 리드 디퓨저** (이미 플랫폼에 들어있는 `reed-diffuser` 처방).
> **왜 디퓨저부터?** 가열·유화·방부가 없어 **가장 쉽고 안전**합니다. 첫 성공에 딱.
> (커리큘럼 `사업_데일리루틴_커리큘럼.md`의 **ACT2 디퓨저**와 그대로 연결됩니다.)
>
> 이 폴더(`docs/실습_따라만들기/`)는 **제품별 따라하기**를 하나씩 쌓는 곳입니다.
> 전체 페이지 레퍼런스는 `docs/UI_사용_가이드.md`를 보세요.
>
> ⚠️ 화면의 라벨/규제/원가 결과는 **1차 스크리닝**입니다. 법적 판단이 아니며,
> 출시 전 반드시 식약처·환경부 고시 원문과 대조하세요.

## 0. UI 실행하기 (제일 먼저)

윈도우 PowerShell에서, 프로젝트 폴더(`c:\myproject\brand`)로 이동한 뒤:

```powershell
# 1) 가상환경 활성화 (이미 만들어 둔 venv 사용)
.\.venv_verify\Scripts\Activate.ps1

# 2) src 폴더를 파이썬 경로에 추가 + 한글 깨짐 방지
$env:PYTHONPATH = "src"
$env:PYTHONIOENCODING = "utf-8"

# 3) 실행
streamlit run streamlit_app.py
```

- 실행되면 브라우저가 자동으로 열립니다(보통 `http://localhost:8501`).
- 안 열리면 터미널에 뜬 **Local URL**을 브라우저에 직접 붙여넣으세요.
- 종료: 터미널에서 **Ctrl + C**.
- `streamlit` 명령이 없다고 하면: `pip install streamlit matplotlib` 후 다시 실행.

> 🔑 **핵심 원리**: 이 UI는 계산을 하지 않습니다. 계산은 전부 `src/brandlab`가 하고,
> 화면은 **YAML 파일(처방·원료·포장)을 읽어 보여줄 뿐**입니다.
> 그래서 **YAML을 수정 → 브라우저 새로고침(F5)** 하면 즉시 반영됩니다. 이게 작업 리듬의 핵심.

첫 화면 상단에 **처방 N종 / 원료 N종 / 포장재 N종** 숫자가 보이면 정상 실행된 겁니다.

## 1. 전체 흐름 한눈에 (이 순서로 클릭합니다)

```
① 규제판정   "이거 무슨 법 적용이지?"      → 디퓨저=화학제품안전법 확인
② 처방       "레시피 보고 배치 계산"        → 100g 배치 지시서 뽑기
③ 사전점검   "만들기 전에 실패 거르기"       → 배합한도·HLB 체크
④ (조향)     "향을 직접 설계할 거면"         → 선택 퀘스트 (지금은 스킵)
─────────────  🧪 여기서 실제로 만든다  ─────────────
⑤ 배치기록   "실제로 만든 결과 기록"        → 수율·관찰 남기기
⑥ 실험       "테스트: DOE·안정성"           → 향 최적화 + 안 변하는지
⑦ 라벨       "표시사항 점검"               → 표시의무·주의문구
⑧ 원가       "팔면 남나?"                  → 손익·마진곡선
⑨ 장바구니   "얼마어치 사야 하지?"          → 구매 목록
```

각 단계는 왼쪽 사이드바의 페이지 하나에 대응합니다. 하나씩 따라가 봅시다.

---

## ① 규제판정 — "이 제품, 무슨 법을 지켜야 하지?"

제품을 만들기 **전에** 어떤 규제를 받는지부터 아는 게 프로의 순서입니다.
디퓨저는 **화장품이 아니라 생활화학제품(화학제품안전법)**이에요. 이걸 화면으로 확인합니다.

**할 일**
1. 사이드바에서 **규제판정** 클릭.
2. 입력값을 이렇게 맞춥니다:
   - **용도**: `space` (공간용)
   - **제형**: `sustained_release` (리드 디퓨저 = 지속 방출)
   - **기능(복수)**: `fragrance` (향)
   - **예상 SKU 수**: `5` · **검토 기간(년)**: `5`
3. 화면이 보여주는 것:
   - **가능한 레짐/카테고리** 표 → `chemical_safety`(생활화학제품)로 분류되는지 확인.
   - **규제비용 비교** 표 → 등록비·SKU 확장비·갱신비·**총 규제비용**·기간(일). ⭐가 최저비용 경로.
   - **적합성** → `OK / CAUTION / REJECT` 판정과 이유.

**여기서 배우는 것**: 디퓨저는 향(SKU)을 늘릴 때마다 규제비용이 어떻게 붙는지.
→ 커리큘럼 ACT5(사업화)에서 다시 쓸 숫자입니다. 지금은 "아, 화장품이랑 다른 법이구나"만 이해하면 충분.

## ② 처방 — "레시피 보고, 만들 양만큼 g 계산"

**할 일**
1. 사이드바 **처방** 클릭.
2. **처방 선택**에서 `reed-diffuser v1 — 라벤더 리드 디퓨저` 선택.
3. 상단 지표 확인: **제품 형태 / 상태(개발중) / 기준 배치(200 g)**.
4. **배치 크기(g) 슬라이더**를 움직여 보세요.
   - 처음엔 작게 **100g**으로 시험 제조 추천(실패 손실 최소화).
   - 슬라이더를 움직이면 아래 표의 **목표 g**가 실시간으로 다시 계산됩니다. (이게 핵심 기능!)
5. **상 A (상온 블렌딩)** 표를 봅니다:
   - DPG 63% · 에탄올 12% · IPM 5% · 라벤더 EO 20% → 각 원료의 목표 g.
   - 공정 설명: "상온에서 용제에 향료를 넣고 맑아질 때까지 저어 혼합".
6. 맨 아래 **⬇️ 배치 지시서 (마크다운) 다운로드** 클릭 → 실험대에서 볼 **작업 지시서**가 파일로 저장됩니다.

**여기서 배우는 것**: 처방(%)은 고정, 배치 크기(g)만 바꾸면 계량값이 자동 환산.
소량 테스트 → 대량 생산으로 그대로 확장됩니다.

> 💡 **향/비율을 바꿔보고 싶다면?** `formulas/reed-diffuser/v1.yaml`을 열어 percent를 수정하고
> (합계 100 유지) 브라우저 **새로고침**하면 화면에 바로 반영됩니다.
> 예: "향이 약하네 → 라벤더 20 → 25로, DPG 63 → 58로". 이게 커리큘럼의 **"안되네, 비율 바꿔보자"** R&D입니다.

## ③ 사전점검 — "만들기 전에 실패를 미리 거른다"

제조 전에 **배합한도 초과**나 **유화 깨짐 위험**을 처방서 숫자만으로 걸러냅니다.

**할 일**
1. 사이드바 **사전점검** 클릭 → `reed-diffuser v1` 선택.
2. 두 가지를 봅니다:
   - **HLB 유화 균형**: 디퓨저는 유화제가 없으니 "해당 없음" 안내가 뜹니다. **정상**입니다.
     (크림·로션을 만들 때 이 항목이 유화 실패를 미리 잡아줍니다 — 나중에 ACT3~4에서 진짜 씁니다.)
   - **배합한도 점검**: 초과·근접 원료가 있으면 표로 뜹니다. 없으면 "초과·근접 원료 없음" ✅.
3. 맨 아래 **종합 사전점검**이 "통과"면 만들어도 되는 처방입니다.

**여기서 배우는 것**: HLB가 "해당 없음"으로 나오는 걸 직접 보면서
**"디퓨저가 왜 쉬운 제형인지"**(유화 실패 위험이 없음)를 몸으로 이해하게 됩니다.

## ④ (선택) 조향 — "향을 직접 설계할 거면"

지금 처방은 라벤더 단일 EO 20%라 이 단계는 **건너뛰어도 됩니다.**
나중에 **여러 향료를 블렌딩**해 나만의 향을 만들 때 씁니다.

**할 일 (하고 싶을 때만)**
1. `formulas/fragrance/`에 향 처방 YAML을 만들면(예: 시트러스+우디 블렌드),
2. 사이드바 **조향** 페이지에서 선택 → **계량표**(희석 배율 반영), **노트 피라미드**(탑/미들/베이스),
   **IFRA 사용한도 체크**, **숙성 완료 알림**을 볼 수 있습니다.

**여기서 배우는 것**: 향 차별화는 여기서 시작됩니다(헤트라스 향 차별화 시나리오 참고).
첫 제품에선 스킵하고, 두 번째 향부터 도전하세요.

## ⑤ 배치기록 — "실제로 만든 결과를 남긴다"

머릿속 기억은 사라집니다. 실제 만든 배치를 기록으로 남겨야 **R&D 자산**이 됩니다.

**할 일**
1. 사이드바 **배치기록** → **새 기록지 생성** 탭.
2. `reed-diffuser v1` 선택, **목표 배치 크기(g)** 입력(예: 100).
3. 자동 생성된 **배치 ID**와 YAML 미리보기 확인.
4. **YAML 내려받기** 또는 **experiments/batches/에 저장** 클릭.
5. 제조 후, 그 파일을 열어 실측값을 채웁니다:
   - `actual_g`(실제 계량 합) / `yield_g`(회수량) / `ph`(디퓨저는 보통 생략) / `observations`(관찰: 향 강도·투명도·층분리 여부).
6. 다시 **기록 요약** 탭에서 배치들이 표로 쌓이는 걸 확인.

**여기서 배우는 것**: **수율**(목표 대비 실제 회수량)과 관찰을 남기는 습관.
이게 나중에 공장에 "우리는 이렇게 재현성 있게 만든다"를 증명하는 근거가 됩니다.

## ⑥ 실험 — "테스트: 향 최적화 + 안 변하는지"

제품 개발의 진짜 핵심 두 가지. 탭이 두 개입니다.

### 6-1. DOE 분석 탭 — "무엇이 향을 지배하는가"
- `experiments/doe/*.yaml`에 실험 설계를 넣으면(예: 향 농도 / 용제비 / 에탄올비 2~3인자),
- 이 화면이 **주효과 표 + 해석 문장 + 주효과·교호작용 플롯**을 그려줍니다.
- "향 농도를 올리면 발향이 +2, 지속은 +1" 같은 결론을 숫자로 얻습니다.
- **여기서 배우는 것**: 감이 아니라 **데이터로 향을 튜닝**. (기존 DOE 시나리오들과 같은 방식)

### 6-2. 안정성 시험 탭 — "시간이 지나도 안 변하나"
- `experiments/stability/*.yaml`에 시료를 등록하면(RT/4℃/45℃ 조건, 주차별 관찰),
- **⏰ 밀린 관찰** 알림 + **조건별 현황**(✓ 완료 / ✗ 지연 / · 예정)을 보여줍니다.
- **여기서 배우는 것**: 관찰일을 놓치면 그 시점 데이터가 사라진다 → 화면이 잔소리해 줍니다.
  디퓨저는 주로 **변색·변취·층분리**를 봅니다.

> 이 두 파일(`doe`, `stability`)은 지금 없을 수 있어요. 그럼 "파일이 없습니다" 안내가 뜹니다.
> 커리큘럼 ACT2 Week3(DOE)·ACT4(안정성)에서 만들면서 이 화면을 채워갑니다.

## ⑦ 라벨 — "표시사항 점검"

**할 일**
1. 사이드바 **라벨** → `reed-diffuser v1` 선택.
2. 디퓨저는 화장품이 아니므로, 화면은 **생활화학제품 레짐 기준**으로 표시의무·주의문구 등을 보여줍니다.
   (화장품 처방을 고르면 전성분·알러젠·배합한도 화면으로 자동 전환됩니다 — 제품 종류에 따라 화면이 바뀝니다.)

**여기서 배우는 것**: 제품 카테고리에 따라 지켜야 할 **표시사항이 다르다**는 것.
화면이 알아서 맞는 규제 화면을 띄워 줍니다.

## ⑧ 원가 — "이거 팔면 남나?"

가장 현실적인 페이지. 여기서 **팔수록 손해**인지 아닌지가 드러납니다.

**할 일**
1. 사이드바 **원가** → `reed-diffuser v1` 선택.
2. **주문 수량**(예: 1000)과 **판매가(부가세 포함)**(예: 34000) 입력.
3. 화면이 보여주는 것:
   - **개당 원가 내역**: 원료비 + 부자재비(병·리드) → **개당 원가**.
   - **개당 손익**: 실매출 − 채널수수료 − 배송비 − 원가 − 반품 → **개당 공헌이익**.
     ⚠️ 공헌이익이 **마이너스**면 "팔수록 손해"입니다(디퓨저는 병값·배송비가 커서 낱개 온라인이 특히 위험 — 시나리오에서 배운 함정).
   - **MOQ 병목**: 병 최소주문수량(MOQ) 때문에 초도 자본이 얼마 묶이는지.
   - **판매가별 마진 곡선**: 가격을 올리면 마진이 어떻게 변하는지 그래프.

**여기서 배우는 것**: "얼마에, 몇 개 이상 팔아야 남는가"를 숫자로.
→ 가격·채널(낱개 vs 묶음/도매) 전략의 근거.

---

## ⑨ 장바구니 — "그럼 얼마어치 사야 하지?"

**할 일**
1. 사이드바 **장바구니** → `reed-diffuser v1` 선택.
2. **구매 기준**: `생산 수량(개)` 또는 `배치 크기(g)` 선택 후 수량 입력.
3. 화면이 **재고를 빼고 부족분만** 공급사 팩·MOQ 단위로 계산해 줍니다:
   - **원료 구매** 표(필요g / 보유g / 부족g / 몇 팩 / 비용).
   - **포장 구매** 표(병 발주량 / 사장재고 / 비용).
   - **총 예상 구매액**.

**여기서 배우는 것**: 재고 관리 + "이번 배치에 딱 얼마 쓰면 되는지". 원료 낭비를 막습니다.

## 2. 한 바퀴 돌고 나면 (마일스톤 연결)

여기까지 클릭했다면, 당신은 이미 **제품 하나의 전 과정**을 UI로 경험한 겁니다:

## 3. 막히면 (초보자 FAQ)

- **화면이 안 뜬다** → 터미널에 뜬 **Local URL**을 브라우저에 직접 입력. 그래도 안 되면 §0 재확인.
- **"처방이 없습니다"** → `formulas/` 폴더가 있는 위치에서 실행했는지, YAML이 올바른지 확인.
- **한글이 깨진다(차트)** → `$env:PYTHONIOENCODING="utf-8"` 설정 확인. 폰트 경고는 나눔고딕 설치로 해결.
- **YAML 고쳤는데 화면이 그대로다** → 브라우저 **새로고침(F5)**. UI는 파일을 다시 읽습니다.
- **percent 합계 오류** → 상별 percent 합이 100이 되도록. 처방 화면 "전체 합계"로 확인.
- **"파일이 없습니다"(DOE/안정성)** → 정상. 아직 실험 파일을 안 만든 것뿐. 커리큘럼 진행하며 채웁니다.

## 4. 다음 실습으로

디퓨저 한 바퀴가 익숙해지면, **같은 9단계**를 다른 처방으로 반복하세요.
이 폴더에 실습을 하나씩 추가해 갑니다:

- **02 (예정)** `face-oil` / `lip-balm` / `cleansing-balm` — 무수 스킨케어(ACT3)
- **03 (예정)** `daily-lotion` — 유화 로션(ACT4, 가장 어려움)
- 그 외 `room-spray`, `fabric-spray`, `fabric-deodorizer` — 다른 생활화학제품

"감이 안 온다"던 개발이 **반복 가능한 루틴**이 됩니다. 그게 이 플랫폼의 목적이에요. 🧪
