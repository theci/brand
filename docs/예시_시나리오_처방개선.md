# 예시 시나리오 ⑨ — 처방을 v1에서 v2로 개선하는 **R&D 루프편** (check · batchlog · diff)

이 문서는 제품을 *처음 만드는* 다른 시나리오들과 성격이 다릅니다. 이미 만든 처방([`예시_시나리오_수분로션.md`](예시_시나리오_수분로션.md)의 **데일리 수분 로션 v1**)을 **어떻게 개선하고, 그 개선이 실제로 좋아졌는지 어떻게 확인하는가** — 즉 **연구개발 반복(iteration) 루프**를 다룹니다.

> 명령은 모두 이 저장소에서 **그대로 실행됩니다.** 결과는 실제로 실행해 얻은 값입니다.
> 1차 스크리닝이며 법적·효능 판단이 아닙니다. 출시 전 관할 기관·시험 성적서가 필요합니다.

## 왜 이 루프가 필요한가 — "감(感)으로 고치기"의 함정

혼자 개발하면 보통 이렇게 됩니다: 비커에 이것저것 더 넣어보고 → "음, 나아진 것 같은데?" → 다음에 또 바꾸고 → **뭘 바꿔서 뭐가 좋아졌는지 기록이 없다.** 배치가 20개쯤 쌓이면 재현이 안 됩니다.

이 저장소는 그걸 3개의 명령으로 막습니다. 각 명령이 루프의 한 단계입니다.

| 단계 | 명령 | 하는 일 | 막아주는 실패 |
|---|---|---|---|
| ① 제조 전 점검 | `check` | HLB 유화 균형 + 배합한도 스캔 | **유화 깨짐·한도 초과**를 비커에 넣기 전에 차단 |
| ② 제조·기록 | `batchlog` | 실측 무게·수율·pH를 처방 버전에 남김 | **재현 불가**(감으로 만든 배치) |
| ③ 버전 비교 | `diff` | v1↔v2 원료·함량·원가 변화 | **"뭘 바꿨는지 모름"·원가 폭증** |

전체 흐름: **check v1 → 파일럿 제조·batchlog → 개선안 v2 작성 → check v2 → 재제조·batchlog → diff v1 v2**.

## STEP 0 — 개선 전, 지금 처방을 사전점검한다 (`check`)

> **"v1을 이미 한 번 만들었다. 개선하기 전에, 이 처방이 애초에 유화가 제대로 되는 조합인지부터 숫자로 확인하자. 물과 기름을 섞는 로션에서 제일 무서운 건 며칠 뒤 층이 갈라지는(층분리) 거니까."**

```bash
uv run brandlab check daily-lotion v1
```
```
╭─────── 처방 사전점검(check) ────────╮
│ 데일리 수분 로션  (daily-lotion v1) │
╰─────────────────────────────────────╯
╭──────────────── HLB 균형: 적합 ────────────────╮
│ 공급 HLB 10.0 ≈ 요구 HLB 9.88 (Δ+0.12) — 유화 안정 예상 │
│ 유화제: glyceryl-stearate-citrate              │
│ 유상: cetyl-alcohol, jojoba-oil, squalane, shea-butter │
╰────────────────────────────────────────────────╯
배합한도 점검
  페녹시에탄올  1% / 한도 1%  (권장상한)  → 도달
  페녹시에탄올  1% / 한도 1%  (배합한도)  → 도달
종합: 통과
```

### ❓ HLB가 뭐길래 "유화 성공"을 미리 안다는 건가

**HLB(Hydrophilic-Lipophilic Balance, 친수-친유 균형값, 0~20)** 은 계면활성제가 "물을 좋아하는 정도"를 숫자로 매긴 것입니다. 핵심 원리 두 가지:

1. **모든 오일에는 그 오일을 O/W(수중유형)로 유화하는 데 필요한 HLB 값**(= required HLB)이 정해져 있습니다. 호호바오일은 6.5, 스쿠알란은 12처럼요.
2. **유화제가 공급하는 HLB**가 그 오일 블렌드의 required HLB와 **맞아야** 유화가 안정됩니다. 어긋나면 며칠 뒤 기름층이 뜹니다(층분리·크리밍).

`check`는 이걸 자동 계산합니다:
- **요구 HLB** = 유상 오일들의 required HLB를 **함량으로 가중평균** → 여기선 9.88
- **공급 HLB** = 유화제들의 HLB를 함량으로 가중평균 → 여기선 10.0 (글리세릴스테아레이트시트레이트)
- **차이 Δ+0.12** → 허용치(±1.0) 안 → **적합**

> **"공급 10.0, 요구 9.88. 거의 딱 맞네. 이 조합은 유화가 안정될 거다. 비커에 넣기 전에 이걸 알았다."**

이게 초보 실패 1순위(유화 깨짐)를 **재료비 한 푼 쓰기 전에** 걸러줍니다.

### ❓ 배합한도 "도달"은 문제인가

페녹시에탄올(보존제)이 **1.0% = 법적 한도 정확히**입니다. `초과`가 아니라 `도달`이라 통과지만, **더 못 올린다**는 뜻입니다. 개선안에서 "보존력을 더 주자"며 페녹시에탄올을 올리면 **위법**이 됩니다. 그래서 STEP 2에서 보존제는 건드리지 않습니다.

✅ **게이트:** HLB `적합`, 한도 `초과` 없음 → 개선을 시작해도 되는 건강한 처방.

## STEP 1 — 100g 파일럿을 만들고 실측을 기록한다 (`batchlog`)

개선하려면 **현재 상태의 실측 데이터**가 있어야 합니다. "감"이 아니라 숫자로요. 먼저 빈 기록지를 만듭니다.

```bash
uv run brandlab batchlog new daily-lotion v1 --grams 100
```
```
배치 기록 생성: DL-20260902-01
experiments/batches/DL-20260902-01.yaml
→ 제조 후 actual_g / yield_g / ph / observations 를 채우세요.
```

생성된 파일에는 **원료별 목표 무게가 이미 채워져** 있습니다(저울 옆에 두고 그대로 계량):

```yaml
batch_id: DL-20260902-01
formula_ref: daily-lotion v1
target_g: 100.0
yield_g: null        # ← 완성 후 무게(g) 기입
ph: null             # ← pH미터 측정값 기입
lines:
  - { id: water, target_g: 78.3, actual_g: null }   # ← 실제 계량값
  - { id: glycerin, target_g: 5.0, actual_g: null }
  - ...
observations: null   # ← 외관·향·사용감 메모
```

**제조 후** 저울·pH미터로 잰 값을 채웁니다(측정 도구를 이미 사셨죠):

```yaml
yield_g: 92.5
ph: 5.2
observations: 유화 양호(층분리 없음). 냉각 후 약간 묽음 → 다음 배치서 잔탄검 0.3→0.4 검토.
```

### ❓ 왜 수율과 pH를 굳이 기록하나

```bash
uv run brandlab batchlog summary
```
```
배치ID           처방              목표g  회수g  수율    pH
DL-20260902-01   daily-lotion v1   100    92.5   92.5%   5.2
```

- **수율 92.5%** = 100g 목표에서 92.5g 회수. 비커·교반날개에 묻어 손실. **90~95%면 정상**입니다(무수 고체보다 손실 큼). 수율이 갑자기 80%로 떨어지면 공정에 문제가 생긴 신호 → 기록이 있어야 알아챕니다.
- **pH 5.2** = 초록색(피부 제품 4.5~6.0 정상). pH가 범위를 벗어나면 사용감·보존력·안정성이 다 흔들립니다. **가장 중요한 정량 지표**.
- **관찰 메모** = 여기서 나온 "약간 묽음"이 **다음 버전의 개선 방향을 직접 결정**합니다. 이게 랩노트의 핵심.

✅ **게이트:** 수율 정상(92.5%), pH 정상(5.2). 이제 **데이터에 근거해** 개선안을 짤 수 있습니다.

---

## STEP 2 — 개선안(v2)을 설계한다: "증량"이 아니라 "다축"

개선 동기는 두 갈래입니다:

1. **배치기록서 나온 문제** — "냉각 후 약간 묽음" → 점증제(잔탄검) 소폭 ↑
2. **USP(차별점) 만들기** — 경쟁 로션과 다르려면? **글리세린을 더 넣는 게 아니라**(끈적여지고 효과는 정체됨), **보습의 다른 축**을 추가합니다.

| 변경 | 원료 | v1 → v2 | 이유(축) |
|---|---|---|---|
| 점도 개선 | 잔탄검 | 0.3 → 0.4 | 배치기록의 '묽음' 해결 |
| 수분막 강화 | 히알루론산 | 0.1 → 0.15 | 습윤 축 보강(고분자 수분막) |
| **USP 신규** | **판테놀(비타민B5)** | ― → 1.0 | **보습+진정 '다른 축'** 추가 |
| 밸런스 | 정제수 | 78.3 → 77.15 | 100% 맞춤 |

> **"핵심은 유상(오일·유화제)은 절대 안 건드린다는 거다. 왜냐면 STEP 0에서 맞춰놓은 HLB 균형이 깨지면 유화가 무너지니까. 수상에서만 보습 축을 손본다."**

새 원료 판테놀을 등록하고(`data/ingredients.yaml`), `formulas/daily-lotion/v2.yaml`을 작성합니다(수상 3줄 변경, 유상 그대로).

### ❓ 왜 유상을 안 건드리는 게 중요한가 — 다시 `check`

```bash
uv run brandlab check daily-lotion v2
```
```
╭──────────────── HLB 균형: 적합 ────────────────╮
│ 공급 HLB 10.0 ≈ 요구 HLB 9.88 (Δ+0.12) — 유화 안정 예상 │
╰────────────────────────────────────────────────╯
종합: 통과
```

유상(오일·유화제)을 그대로 뒀으니 **HLB가 v1과 동일(적합)** 입니다. 즉 **"유화 안정성은 유지한 채, 보습 성능만 손봤다"** 가 숫자로 증명됩니다. 만약 오일을 하나 추가했다면 required HLB가 바뀌어 유화가 흔들렸을 텐데, `check`가 그걸 즉시 잡아줍니다.

✅ **게이트:** v2도 HLB `적합`. 개선이 유화를 망가뜨리지 않았음을 **제조 전에** 확인.

## STEP 3 — v2를 재제조하고 개선을 확인한다 (`batchlog`)

```bash
uv run brandlab batchlog new daily-lotion v2 --grams 100
# → DL-20260902-02.yaml 생성, 제조 후 실측 기입
```

제조·측정 후:
```yaml
yield_g: 93.0
ph: 5.3
observations: 잔탄검 0.4로 점도 개선(묽음 해소). 유화 양호·층분리 없음. 판테놀 후 발림 부드러움.
```

```bash
uv run brandlab batchlog summary
```
```
배치ID           처방              목표g  회수g  수율   pH
DL-20260902-01   daily-lotion v1   100    92.5   92.5%  5.2
DL-20260902-02   daily-lotion v2   100    93     93%    5.3
```

> **"수율·pH는 그대로 건강하고, v1에서 걸렸던 '묽음'이 해결됐다. 관찰 메모로 개선이 실제 반영됐음을 남긴다."**

### ❓ "보습이 진짜 좋아졌나"는 여기서 증명 못 한다 — 정직하게

배치기록으로 확인되는 건 **수율·pH·안정성·사용감(관찰)** 까지입니다. **"보습력이 올랐다"는 효능**은 각질층 수분(코네오미터)·수분증발량(TEWL) 같은 **기기로 외부 랩에서** 측정해야 하고, 그 성적서가 있어야 광고에 쓸 수 있습니다(안 그러면 표시광고법 위반 — `lint` 명령이 잡는 영역). **개발 반복은 집에서, 효능 실증은 랩에서.**

✅ **게이트:** v2 배치 정상 + 묽음 해소. 개발 관점 개선 완료.

---

## STEP 4 — v1과 v2를 비교한다: 무엇이·얼마에 바뀌었나 (`diff`)

```bash
uv run brandlab diff daily-lotion v1 v2
```
```
╭─────── 처방 비교(diff) ───────╮
│ daily-lotion  v1 → v2          │
╰────────────────────────────────╯
원료 함량 변화
  정제수                     78.3 → 77.15   -1.15   감량
  글리세린                      5 → 5         +0     유지
  소듐하이알루로네이트          0.1 → 0.15   +0.05   증량
  판테놀(프로비타민B5)          ―  → 1        신규
  잔탄검                        0.3 → 0.4    +0.1    증량
  글리세릴스테아레이트시트레이트  5 → 5        +0     유지
  … (유상·냉각 원료는 전부 유지) …
개당 원가 변화 (수량 1,000개 기준)
  개당 원료비   306원 → 330원   +24원
  개당 원가   1,106원 → 1,130원  +24원
```

### ❓ 이 표 하나로 무엇을 판단하나

- **바뀐 것만 한눈에**: 신규(판테놀)·증량(히알루론산·잔탄검)·감량(정제수). 유상은 전부 `유지` → **"유화는 안 건드리고 보습만 손봤다"** 는 전략이 그대로 보입니다.
- **원가 델타 +24원**: USP(판테놀·히알루론산)를 더했는데 개당 원료비가 306→330원, **24원만** 늘었습니다. 22,000원짜리 제품에서 24원은 무시할 수준 → **"이 개선은 원가 리스크 없이 차별점을 얻었다"** 는 의사결정 근거.
- 만약 델타가 +2,000원이었다면? "이 USP는 원가를 너무 올린다, 히어로 원료를 더 싼 걸로" 같은 판단을 **숫자로** 하게 됩니다.

✅ **게이트:** 개선 내용·원가 영향이 문서화됨. v2를 `status: 확정`으로 올릴지 결정 가능.

## 한눈 요약 — R&D 반복을 도구로 굴린다는 것

| 단계 | 명령 | 이 시나리오에서 얻은 값 | 판단 |
|---|---|---|---|
| 사전점검 | `check v1` | HLB 10.0/9.88 적합, 페녹시에탄올 한도 도달 | 건강한 처방, 보존제는 못 올림 |
| 제조·기록 | `batchlog v1` | 수율 92.5%, pH 5.2, "묽음" 관찰 | 개선 방향 = 점도↑ |
| 개선설계 | (다축 전략) | 판테놀 신규 + 히알루론산·잔탄검↑ | 증량 아닌 **다축 USP** |
| 재점검 | `check v2` | HLB 여전히 적합 | 유화 안 망가뜨림 |
| 재제조 | `batchlog v2` | 수율 93%, pH 5.3, 묽음 해소 | 개선 확인 |
| 비교 | `diff v1 v2` | 판테놀 신규, 개당 **+24원** | 원가 리스크 없이 차별화 |

> **핵심**: 감으로 고치지 않습니다. **check로 실패를 미리 막고 → batchlog로 실측을 남기고 → diff로 변화와 원가를 확인**합니다. 이 루프를 돌 때마다 처방 버전(v1, v2, v3…)과 배치 기록이 쌓여, **재현 가능한 개발 이력**이 됩니다.
